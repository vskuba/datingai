# Docs Common — универсальные правила для всех проектов

> Здесь лежит документация **без привязки к конкретному проекту**: правила, которые
> действуют одинаково во всех репозиториях. Всё, что содержит имена таблиц, порты,
> контейнеры, роуты и прочие детали одной инсталляции, живёт в `.claude/docs/`.

## Как разделять `docs-common/` и `docs/`

| | `.claude/docs-common/` | `.claude/docs/` |
|--|------------------------|-----------------|
| Что описывает | правило, принцип, паттерн | как это реализовано здесь |
| Пример | «схема живёт в одном файле миграции» | «схема — `migrations/0001.sql`» |
| Пример | «страница регистрируется в карте меню» | «допиши URL в `groupMap` в `base.html`» |
| Переносимость | копируется в новый проект как есть | не имеет смысла вне проекта |

Практический тест: **если файл нельзя скопировать в пустой новый проект без правок —
он не для `docs-common/`.** Конкретика заменяется на роль: не `migrations/0001.sql`,
а «единственный DDL-файл»; не `uvicorn`, а «контейнер приложения».

## Состав

| Файл | Содержимое |
|------|-----------|
| `code_rules.md` | Именование функций и констант, приватные внизу, дробление файлов, ветки размещения |
| `api_rules.md` | Контракт ответов, формат ошибок, разделение роутеров, валидация входа |
| `auth_rules.md` | Сессии, RBAC, проверка по возможностям (не по имени роли), полевые политики |
| `database_rules.md` | Единственный источник схемы, DDL против данных, порядок FK, идемпотентность, прод |
| `backup_rules.md` | Seed против бэкапа, экспорт/восстановление, безопасность имён файлов |
| `env_config_rules.md` | `.env` / `.dist` / `.local`, секреты, таблица настроек, конфиг для фронтенда |
| `frontend_rules.md` | SSR-страницы админки, чек-лист новой страницы, локальность стилей, без CDN |
| `deploy_rules.md` | Blue-Green, конфиг-файл как источник истины, healthcheck, откат |
| `tool_rules.md` | Автообнаруживаемые инструменты: контракт функции, докстринг для LLM, ошибки |
| `llm_rules.md` | Мульти-провайдерная маршрутизация, приоритет и фоллбэк, параллельность, журнал |
| `observability_rules.md` | Трейс выполнения, «сбой журнала не роняет процесс», обрезка, чистка |
| `testing_rules.md` | Интеграционная сюита, тестовая учётка, проверка после реализации |
| `docs_rules.md` | Формат документации: структура файла, тон, что не писать |

## Правила самой этой папки

1. **Один файл — одна тема.** Ориентир — до ~200 строк; больше — сигнал делить.
2. **Имена** — lowercase snake_case, суффикс `_rules` для файлов-правил.
3. **Никаких секретов и хостов.** Ни паролей, ни доменов, ни IP — даже в примерах.
4. **Примеры кода — обобщённые.** `<entity>`, `<domain>`, `<namespace>` вместо реальных имён.
5. **Правило добавляется, когда наступили на грабли дважды.** Умозрительные best practices
   без истории отладки в этой папке не нужны.
