# Ручки проекта

Все под входом (сессия или токен), кроме `/login`, `/auth/login`, `/health` и
статики. Ответ — всегда `{"result": …}`; ошибка — `{"detail": "..."}` с внятным
кодом.

Роли две: `dating` (анкеты) и `admin` (плюс устройство установки). Помеченное
ниже **🔒 admin** оператору отдаёт 403 — см. `auth.md`.

## 1. Вход

| Метод | Путь | Что делает |
|-------|------|------------|
| `POST` | `/auth/login` | Заводит сессию. Не сошлось — 401 без подробностей о том, что именно |
| `POST` | `/auth/logout` | Гасит сессию. Повторный выход не ошибка |
| `GET` | `/auth/me` | Кто сейчас в сессии: имя и роль — для шапки страницы |

## 2. Страницы

| Путь | Что отдаёт |
|------|-----------|
| `/` | Панель анкет |
| `/admin/dating` | Она же. Оставлен ради ссылок, сохранённых до переезда |
| `/admin/dating/export` | Экспорт анкет: выгрузка списка профилей с сайта |
| `/admin/seed` | 🔒 admin. Seed SQL: выгрузка выбранных таблиц и заливка обратно |
| `/admin/backup` | 🔒 admin. Резервные копии: полный дамп базы и восстановление |
| `/admin/users` | 🔒 admin. Пользователи: учётки панели, роли и токены доступа |
| `/login` | Форма входа |
| `/health` | `{"status": "ok"}` — для compose и внешнего опроса |

## 3. Анкеты — `/api/dating/profile`

| Метод | Путь | Что делает |
|-------|------|------------|
| `GET` | `` | Список учёток. Пароля в ответе нет — только `has_password` |
| `POST` | `` | Завести учётку. Тот же логин на том же сайте — 409 |
| `PUT` | `/{id}` | Правка. Пустой пароль оставляет прежний |
| `DELETE` | `/{id}` | Удалить вместе с перепиской, журналом и собеседницами |
| `POST` | `/{id}/login` | Вход на сайт: сценарий у соседа, чтение анкеты, снятие входа и адреса сокета |
| `POST` | `/{id}/check` | Полная проверка: вход → чат → чтение → пробная отправка → агент |
| `POST` | `/{id}/listen` | Послушать сокет заданное время (отладка) |
| `POST` | `/{id}/send` | Отправить сообщение собеседнику |
| `POST` | `/{id}/answer` | Ответить агентом на неотвеченное |
| `PUT` | `/{id}/auto` | Включить/выключить автоответ; включение сразу разбирает накопившееся |
| `POST` | `/{id}/dialog` | Прочитать диалоги со страницы чата |
| `POST` | `/{id}/disconnect` | Выход на сайте, закрытие вкладок, снятие с мониторинга |
| `GET` | `/{id}/message` | Переписка для панели |
| `POST` | `/{id}/read` | Пометить прочитанным |
| `GET` | `/{id}/log` | Журнал работы по учётке |
| `GET` | `/{id}/card` | Анкета и страница собеседниц для правой колонки |
| `POST` | `/probe` | Опросить присутствие всех учёток сайта разом |

### Собеседницы приходят страницей

`GET /{id}/card?page=1` — по 50 собеседниц. В ответе рядом с `contacts` идут
`contacts_total`, `page` и `pages`; номер за концом списка ручка исправляет сама и
возвращает исправленный, чтобы странице было с чем сверить пейджер.

Порядок задаёт **база, а не страница**: сначала те, кому не ответили
(`needs_answer`), внутри группы — по свежести последней реплики. Считать признак в
Python после `LIMIT` нельзя: собеседница с давним неотвеченным сообщением в
выборку не попадёт вовсе, а это ровно та работа, ради которой сортировку и просят.

Пагинация здесь серверная, в отличие от списка анкет (тот приходит целиком и
режется на странице): на каждую показанную собеседницу идёт отдельный запрос за
последними десятью репликами, и «отдать всё» при четырёх сотнях означало бы
четыреста запросов на одно открытие карточки.

## 3.1 Экспорт анкет — `/api/dating/export`

| Метод | Путь | Что делает |
|-------|------|------------|
| `POST` | `/profile?site_id=…` | Гонит сценарий выгрузки и отдаёт список профилей таблицей |

Ничего не сохраняет: своей таблицы у выгрузки нет, страница показывает пришедшее
и забывает. Смысл в том, чтобы посмотреть, кто есть на сайте сейчас, а не завести
вторую копию чужого каталога рядом со своей базой.

Сценарий ищется у соседа **по имени** — `экспорт анкет`. Не по подстановкам, как
сценарий входа: подстановок у выгрузки нет (она ходит по открытому каталогу, без
входа под анкетой), и узнать её по ним невозможно.

Ответ:

```json
{"result": {"status": "ok", "scenario": "экспорт анкет",
            "columns": ["name", "age"],
            "profiles": [{"name": "Anna", "age": "25"}],
            "step_no": 0, "error": ""}}
```

**Упавший сценарий приходит с кодом 200**, а `status` в нём — `error`. Правило
взято у самого RhapsodyAi: код ответа говорит про запрос, а не про результат
сценария. Сценарий, вставший на третьем шаге, — законный ответ «вот что вышло»;
отдай мы 500, «сайт поменял вёрстку» стало бы неотличимо от «панель сломалась».

Колонки — имена шагов `extract` сценария, в их порядке. Новая колонка на странице
заводится новым шагом у соседа, а не правкой кода здесь. Как из `extract`
получается таблица — `dating.md`, §6.4.

Отказы: 422 — не выбран сайт или у сайта нет сценария выгрузки; 502 — сосед не
ответил.

## 4. Сайты — `/api/site`

| Метод | Путь | Что делает |
|-------|------|------------|
| `GET` | `` | Сайты-закладки RhapsodyAi для селекта на странице |

Своей таблицы сайтов нет. Ручка тонкая: страница спрашивает свой сервер, сервер —
соседа. Напрямую из браузера нельзя — служебный токен живёт на сервере и в
разметку попадать не должен.

## 5. Seed SQL — `/api/seed` 🔒 admin

| Метод | Путь | Что делает |
|-------|------|------------|
| `GET` | `/table` | Таблицы базы по группам; у каждой `default` — отмечать ли при первом заходе |
| `GET` | `/file` | Что уже выгружено, свежие сверху |
| `POST` | `/generate` | Выгружает выбранные таблицы в новый файл |
| `POST` | `/apply/{name}` | Заливает файл в базу (`INSERT IGNORE`) |
| `GET` | `/download/{name}` | Отдаёт файл |
| `DELETE` | `/{name}` | Удаляет файл |

**Имена таблиц сверяются со списком базы** до того, как попасть в запрос: именем
таблицы параметр не подставить, и брать его из тела на веру значило бы отдать
наружу выполнение произвольного SQL. Чужое имя — 400, а не молчаливый пропуск.

Из списка убраны служебные таблицы мигратора (`_yoyo_*`, `yoyo_lock`): их ведёт
он сам, и залитые из чужой установки они означают «схема уже накачена» на базе,
где её нет. Переписка, журнал и собеседницы в списке есть, но по умолчанию не
отмечены — их наполняет работа панели, а не человек.

Выбор отмеченных таблиц **на сервере не хранится**: у соседа он лежит в таблице
`setting`, заводить её здесь ради набора галочек — платить схемой за настройку.
Помнит выбор страница (`localStorage`), сервер получает список явно с запросом.

Автоприменения при старте нет: seed заливается только нажатием. Первый
пользователь на свежей базе и так заводится сам (`auth_seed_first_user`), а
молча дописывать данные при каждом перезапуске — верный способ получить в базе
то, чего туда не клали.

## 6. Бэкапы — `/api/backup` 🔒 admin

| Метод | Путь | Что делает |
|-------|------|------------|
| `GET` | `/file` | Что уже снято, свежие сверху |
| `POST` | `/create` | Снимает дамп всей базы (`mysqldump`, gzip) |
| `POST` | `/restore/{name}` | Заливает дамп обратно — **перезаписывает базу целиком** |
| `GET` | `/download/{name}` | Отдаёт файл |
| `DELETE` | `/{name}` | Удаляет. Единственный оставшийся — 409 |

Отличие от seed не в размере, а в назначении: seed переносит между установками
то, что завели руками, и ложится поверх живой базы; бэкап — снимок всей базы на
случай аварии. Перепутать их — потерять день работы, поэтому и страницы разные.

Пароль уходит в `mysqldump` и `mysql` через `MYSQL_PWD`, а не аргументом:
аргументы видны в `ps` любому, кто зашёл в контейнер. Клиент стоит в образе
(`default-mysql-client`) — без него дамп снимался бы, а восстановиться из него
было бы нечем, и выяснилось бы это ровно тогда, когда восстановление и требуется.

Обе выгрузки идут в отдельном потоке (`asyncio.to_thread`): в этом же процессе
висят чат-сокеты анкет, и таблица, прочитанная в цикле событий, оборвала бы их
все. Файлы лежат в `data/seeds` и `data/backups`, в репозиторий не попадают: в
них пароли учёток и вся переписка.

## 6.1 Пользователи — `/api/users` 🔒 admin

| Метод | Путь | Что делает |
|-------|------|------------|
| `GET` | `` | Учётки с ролями и токенами. Хеша пароля и значений токенов в ответе нет |
| `POST` | `` | Завести учётку. Имя занято, короткий пароль, чужая роль — 422 |
| `PUT` | `/{id}` | Пароль и роль. **Пустое поле — «не трогать»**, а не «поставить пустым» |
| `DELETE` | `/{id}` | Удалить учётку вместе с её токенами. Анкеты и переписка остаются |
| `POST` | `/{id}/token` | Выдать токен. **Значение приходит только в этом ответе** |
| `DELETE` | `/token/{id}` | Отозвать токен. Действует сразу — токен читается на каждый запрос |

Токен виден целиком один раз, при выдаче; в списке — только пометка и последние
шесть знаков. Иначе открытая страница показывала бы действующие ключи всякому,
кто стоит за спиной, а скриншот раздела раздавал бы их насовсем. Потерянный
токен не восстанавливают: отзывают и выдают новый.

**Себе нельзя менять роль и себя нельзя удалять** — 422. Это не вкусовщина:
понизив себя, администратор теряет доступ к этой самой странице, и вернуть роль
ему будет некому. Пароль себе менять можно — иначе сменить его было бы негде.
Подробности и третий запрет («последний администратор») — в `auth.md`, §5.1.

## 7. Коды ответов

| Код | Когда |
|-----|-------|
| 400 | Недопустимое имя файла или незнакомая таблица в seed |
| 401 | Нет входа (для браузера — редирект на `/login`) |
| 403 | Роль не та: `dating` полез в seed, бэкапы, пользователей или их страницы. Браузеру — страницей, скрипту — `{"detail": …}` |
| 404 | Нет такой учётки или файла |
| 409 | Логин на этом сайте уже заведён; удаление единственного бэкапа |
| 422 | Неверный ввод — **одной фразой**, а не списком объектов; либо нет такого сайта, не настроен опрос присутствия, нет сценария входа; либо запрещённая правка себя (роль, удаление) |
| **502** | **RhapsodyAi не ответил или ответил отказом** |
| 500 | Наша поломка — с текстом, а не пустым обрывом соединения |

Про 422 отдельно. FastAPI по умолчанию отвечает списком объектов
(`[{"type": "string_too_short", "loc": ["body", "password"], …}]`) — исчерпывающе
для клиента и нечитаемо для человека: страница печатала эту простыню прямо в
форму входа. `uvicorn_validation_handler` переводит её в одну фразу («Заполните
пароль») по **типу** ошибки и имени поля, а не по английскому тексту pydantic:
текст меняется от версии к версии, тип и путь — нет.

502 отделён намеренно: «сосед недоступен» — не наша внутренняя ошибка и не вина
того, кто нажал кнопку. В панели должно быть написано «RhapsodyAi недоступен», а
не «что-то пошло не так».
