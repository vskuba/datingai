# CLAUDE.md

## Project Overview

**DatingAi** — панель анкет на сайтах знакомств. Один вход: `main_uvicorn.py`
(FastAPI + серверные страницы) и один воркер (`rq`, очередь `dating`).

Проект делает ровно одно: **держит учётки анкет, показывает их страницами и ведёт
живой чат вебсокетом**. Роль учётки — `lady` или `man`: мужской и женский кабинеты
сайта это разные приложения, и сценарии для них разные. Всё, что требует браузера
и мозгов, живёт в соседнем проекте **RhapsodyAi** и приходит сюда по HTTP:

| Что | Где живёт | Как получаем |
|-----|-----------|--------------|
| сценарии сайтов, пул Chromium | RhapsodyAi | `POST /api/browser/scenario/{id}/run` |
| списки собеседников, если у сайта есть API | **сам сайт** | `POST /auth/login`, `GET /users/{state}` |
| закладки сайтов и `presence` | RhapsodyAi | `GET /api/browser/site/{id}` |
| ⚠ список сайтов — **снимок его ответа** у нас | RhapsodyAi → `dating_site` | сверка в фоне, показываем своё |
| агенты, workflow, факты | RhapsodyAi | `POST /agent/create`, `GET /agent/name/{name}` |
| ответы в чате (LLM) | RhapsodyAi | `POST /chat/ask` |
| учётки, переписка, журнал | **здесь** | своя база `dating` |

Единственная дверь **к соседу** — `src/rhapsody/rhapsody_api.py`. Прямых обращений
к чужим таблицам в коде нет и быть не должно: своей копии сценариев и агентов здесь
не заводится.

Наружу при этом ведут две двери, и вторая — **сам сайт знакомств**: присутствие
(`src/dating/dating_presence.py`), чат и отправка (`src/dating/site/`), а с
недавних пор и списки собеседников (`src/dating/dating_people_api.py`), если у
сайта есть своё API. Браузер и сценарии остаются у соседа.

⚠ **Одно исключение — список сайтов, и оно осознанное.** Селект сайта стоит в шапке
каждой страницы раздела: лежит сосед — селект пуст, и панель целиком выглядит
сломанной, хотя наши данные на месте. Поэтому в `dating_site` лежит **снимок** его
списка (имя, адрес, метки, время сверки), показываем всегда его, а сверяем в фоне.
Ведёт список по-прежнему он: ручки «завести сайт» здесь нет, ушедшие у него
метятся `is_gone`. Подробности и цена размена — `api.md`, §3.5.

`py_modules/` — общая библиотека (отдельный репозиторий) | `src/` — код проекта

См. `.claude/docs/quickstart.md` — запуск и переменные окружения.

**Универсальные правила — в `.claude/docs-common/`** (индекс:
`.claude/docs-common/readme.md`). Там правила без привязки к проекту: именование,
контракт API, права, схема БД, деплой, тесты, формат документации.
`.claude/docs/` описывает, как это реализовано именно здесь. При расхождении
конкретика из `.claude/docs/` — актуальнее.

⚠ **Четыре расхождения — намеренные, и «приводить к общему правилу» их не надо.**
Каждое записано там, где о нём вспомнят, вместе с признаком, по которому решение
стоит пересмотреть:

| Общее правило | Здесь | Где объяснено |
|---------------|-------|---------------|
| RBAC: права-возможности, роли в БД, сессия в БД | две роли константами, `is_admin`, подписанная кука | `auth.md`, §7 |
| сюита ходит под отдельной неадминской учёткой | под теми же, что и человек | `testing.md`, §1 |
| сюита целиком по HTTP против поднятого приложения | часть тестов зовёт обработчики в процессе | `testing.md`, §1.2 |
| Blue-Green со слотами и быстрым откатом | простой перезапуск | `deploy.md`, §3.1 |

## Development Patterns

- **Новая ручка API** → `.claude/docs/api.md`
- **Обращение к RhapsodyAi** → `.claude/docs/rhapsody_api.md`
- **Правка страницы** → `.claude/docs/dashboard_frontend.md`
- **Своя разметка под сайт** → `data/uvicorn/template/admin/profile/site/` (⚠ наследованием от `_base.html`, а не копией)
- **Изменение схемы** → `.claude/docs/migration.md` (новый файл в `migrations/`, применённые не правят)
- **Работа воркера** → `.claude/docs/worker.md`
- **Новый сайт знакомств** → `.claude/docs/dating.md`, §5.0 (драйвер сайта: настройкой или файлом)
- **Импорт анкет с сайта** → `.claude/docs/dating.md`, §6.5 (сценарии у соседа, кнопка на «Профилях»)
- **Импорт переписки из панели** → `.claude/docs/dating.md`, §5.8 (⚠ ложится в `dating_message`; `source = 'panel'` не даёт истории уехать в автоответ)
- **Новый прогон сценария** → `src/dating/dating_scenario.py` (⚠ только через него: иначе прогон не попадёт в журнал)
- **Новая настройка сайта** → `.claude/docs/api.md`, §3.5 (ключ в `dating_site.settings`, страница «Сайты»; секрет — пометкой в реестре)
- **Списки собеседников с сайта** → `.claude/docs/api.md`, §3.3 (⚠ источник — настройка `people_source`: API сайта или сценарий у соседа)
- **Новая настройка панели** → `.claude/docs/api.md`, §6.2 (строка в `setting`, страница «Настройки → Значения»)
- **Показ даты или времени** → `data/uvicorn/public/js/dating_time.js` (⚠ с сервера всё приходит **в UTC**; сдвигает страница по настройке `timezone`)
- **Отказ, который не про анкету** → `src/dating/dating_error.py` (⚠ строка одна на источник; удача её стирает)
- **Работа с прод-базой или ssh на прод** → `.claude/docs/deploy.md`, §4.5 (⚠ бэкап до записи; защитные правки — отдельным запросом; `--default-character-set=utf8mb4`)
- **Проверка после правок** → `.claude/docs/testing.md` (⚠ тесты наружу не ходят: ни к соседу, ни на сайт — заглушки в `tests/rhapsody_fake.py` и `tests/site_api_fake.py`)
