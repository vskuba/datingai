# CLAUDE.md

## Project Overview

**DatingAi** — панель анкет на сайтах знакомств. Один вход: `main_uvicorn.py`
(FastAPI + серверные страницы) и один воркер (`rq`, очередь `dating`).

Проект делает ровно одно: **держит учётки анкет, показывает их страницами и ведёт
живой чат вебсокетом**. Роль учётки — `lady` или `man`: мужской и женский кабинеты
сайта это разные приложения, и сценарии для них разные. Всё, что требует браузера
и мозгов, живёт в соседнем проекте **RhapsodyAi** и приходит сюда по HTTP:

| Что | Где живёт | Как получаем |
|-----|-----------|--------------|
| сценарии сайтов, пул Chromium | RhapsodyAi | `POST /api/browser/scenario/{id}/run` |
| списки собеседников, если у сайта есть API | **сам сайт** | `POST /auth/login`, `GET /users/{state}` |
| закладки сайтов и `presence` | RhapsodyAi | `GET /api/browser/site/{id}` |
| ⚠ список сайтов — **снимок его ответа** у нас | RhapsodyAi → `dating_site` | сверка в фоне, показываем своё |
| агенты, workflow, факты | RhapsodyAi | `POST /agent/create` (обязателен `site`), `GET /agent/name/{name}` |
| ответы в чате (LLM) | RhapsodyAi | `POST /chat/ask` |
| учётки, переписка, журнал | **здесь** | своя база `dating` |

Единственная дверь **к соседу** — `src/rhapsody/rhapsody_api.py`. Прямых обращений
к чужим таблицам в коде нет и быть не должно: своей копии сценариев и агентов здесь
не заводится.

Агент заводится **с меткой сайта**: у соседа поле `site` обязательное и проверяется
форматом `^[a-z0-9]+$` — не подойдёт, и заведение отвечает `422`. Метку собирает
`dating_agent_site` из имени сайта-закладки: `Goldenbride` → `goldenbride`,
`Ladadate` → `ladadate`. Имя берётся из справочника соседа по `dating_profile.site_id`,
своего списка сайтов здесь нет. Имя не сводится к латинице — заведение не идёт вовсе:
подставить общую метку значило бы приписать анкету чужому сайту.

Наружу при этом ведут две двери, и вторая — **сам сайт знакомств**: присутствие
(`src/dating/dating_presence.py`), чат и отправка (`src/dating/site/`), а с
недавних пор и списки собеседников (`src/dating/dating_people_api.py`), если у
сайта есть своё API. Браузер и сценарии остаются у соседа.

⚠ **Одно исключение — список сайтов, и оно осознанное.** Селект сайта стоит в шапке
каждой страницы раздела: лежит сосед — селект пуст, и панель целиком выглядит
сломанной, хотя наши данные на месте. Поэтому в `dating_site` лежит **снимок** его
списка (имя, адрес, метки, время сверки), показываем всегда его, а сверяем в фоне.
Ведёт список по-прежнему он: ручки «завести сайт» здесь нет, ушедшие у него
метятся `is_gone`. Подробности и цена размена — `api.md`, §3.5.

`py_modules/` — общая библиотека (отдельный репозиторий) | `src/` — код проекта

См. `.claude/docs/quickstart.md` — запуск и переменные окружения.

**Универсальные правила — в `.claude/docs-common/`** (индекс:
`.claude/docs-common/readme.md`). Там правила без привязки к проекту: именование,
контракт API, права, схема БД, деплой, тесты, формат документации.
`.claude/docs/` описывает, как это реализовано именно здесь. При расхождении
конкретика из `.claude/docs/` — актуальнее.

⚠️ `.claude/docs-common` — **симлинк на `py_modules/docs`**, общий для всех проектов.
Читается как обычная папка, но правка через него меняет общий репозиторий: коммит идёт в
`py_modules`, и её увидят соседние проекты. Проектной конкретике там не место.

⚠ **Четыре расхождения — намеренные, и «приводить к общему правилу» их не надо.**
Каждое записано там, где о нём вспомнят, вместе с признаком, по которому решение
стоит пересмотреть:

| Общее правило | Здесь | Где объяснено |
|---------------|-------|---------------|
| RBAC: права-возможности, роли в БД, сессия в БД | две роли константами, `is_admin`, подписанная кука | `auth.md`, §7 |
| сюита ходит под отдельной неадминской учёткой | под теми же, что и человек | `testing.md`, §1 |
| сюита целиком по HTTP против поднятого приложения | часть тестов зовёт обработчики в процессе | `testing.md`, §1.2 |
| Blue-Green со слотами и быстрым откатом | простой перезапуск | `deploy.md`, §3.1 |

## Development Patterns

- **Новая ручка API** → `.claude/docs/api.md`
- **Обращение к RhapsodyAi** → `.claude/docs/rhapsody_api.md`
- **Правка страницы** → `.claude/docs/dashboard_frontend.md`
- **Своя разметка под сайт** → `data/uvicorn/template/admin/profile/site/` (⚠ наследованием от `_base.html`, а не копией)
- **Изменение схемы** → `.claude/docs/migration.md` (новый файл в `migrations/`, применённые не правят)
- **Работа воркера** → `.claude/docs/worker.md`
- **Новый сайт знакомств** → `.claude/docs/dating.md`, §5.0 (драйвер сайта: настройкой или файлом)
- **Импорт анкет с сайта** → `.claude/docs/dating.md`, §6.5 (сценарии у соседа, кнопка на «Профилях»)
- **Чтение таблиц админ-панели** → `src/dating/dating_panel_fetch.py` (⚠ сайт с `admin_url` читается **ручкой по сессии**, без `admin_url` — сценарием; даты панель понимает только как `дд.мм.гггг`, на ISO молча отдаёт свой срок)
- **Импорт переписки из панели** → `.claude/docs/dating.md`, §5.8 (⚠ ложится в `dating_message`; `source = 'panel'` не даёт истории уехать в автоответ)
- **Новый прогон сценария** → `src/dating/dating_scenario.py` (⚠ только через него: иначе прогон не попадёт в журнал)
- **Новая настройка сайта** → `.claude/docs/api.md`, §3.5 (ключ в `dating_site.settings`, страница «Сайты»; секрет — пометкой в реестре)
- **Шаблон письма или переменная** → `.claude/docs/api.md`, §3.7 (⚠ три места: имя в реестре сайта, значение у анкеты, ссылка в тексте; не сошлись — письмо не уходит)
- **Пул писем и рассылка** → `.claude/docs/api.md`, §3.7.2 (⚠ шаблон несёт метки, пул несёт значения; отправляет человек кнопкой, кругового отправителя нет)
- **Обращение к API сайта знакомств** → `src/dating/dating_site_api.py` (⚠ только через него: токен один на анкету, два входа сайт считает подозрением)
- **Админ-панель сайта: ссылка и состояние** → `.claude/docs/api.md`, §3.11 (⚠ адрес — страница **после входа**, а не корень: корень уводит переадресацией и вошедшего; без приметы `admin_mark` форма входа считается кабинетом)
- **Анкета видна в сети** → `.claude/docs/heartbeat.md` (⚠ это **не чат**: «в сети» держит HTTP-удар по таймеру, «в чате» — вебсокет; сокет есть не у всех сайтов, присутствие нужно всем)
- **Что круги делают прямо сейчас** → `.claude/docs/api.md`, §3.12 (⚠ щелчок по строке ленты **ведёт** к результату: вид события → вкладка)
- **Черновик анкеты, которой нет в сети** → `.claude/docs/api.md`, §3.7.8 (⚠ круг чистит пул **до** счёта места, иначе увидит его полным и уйдёт ни с чем)
- **Рассылка по расписанию** → `.claude/docs/api.md`, §3.7.3 (⚠ два срока: смены задают часы, `mailing_every` — частоту внутри них)
- **Входящие письма** → `.claude/docs/api.md`, §3.7.4 (⚠ забор — первый в цепочке: снят, и ответов тоже не будет. Единственный выключатель почты, включённый по умолчанию — он только читает)
- **Ответы на входящие** → `.claude/docs/api.md`, §3.7.4 (⚠ пул набирает круг, кнопки нет; расписание здесь не спрашивается)
- **Отправка наружу** → `.claude/docs/api.md`, §3.7.5 (⚠ единственное место, откуда письмо уходит живому человеку: два выключателя, пауза, потолок в сутки)
- **Агент у соседа под новое занятие** → миграция в `RhapsodyAi/migrations/` (workflow там — данные, а не код) + вызов в `src/dating/dating_mail_agent.py`
- **Описание собеседника с сайта** → `src/dating/dating_companion_about.py` (⚠ сценарий «анкета мужчины: карточка» у соседа; вход под той девушкой, от которой письмо)
- **Найти HTTP-ручку вместо сценария** → перехват сети у соседа: шаги `net_watch` / `net_dump` (`RhapsodyAi/.claude/docs/browser.md`; ⚠ заголовки пишутся по закрытому списку — `cookie` в `extract` не уедет)
- **Отправка в чат LadaDate** → `.claude/docs/dating.md`, §5.9 (⚠ идёт **ручкой сайта**, не сценарием: 277 мс против 60 секунд. Признак удачи `IsSuccess`, а не код 200; тело кодируется **дважды** — `encode: js_escape_form`; каждой анкете нужна живая сессия)
- **Статистика панели** → `.claude/docs/api.md`, §3.10 (⚠ анкета — **фильтр**; «исходящее» это **ушедшее**, черновик отдельной строкой; токены считает сосед и только за 7 дней, по узлу, а не по анкете)
- **Инвайты: первая реплика в чат** → `.claude/docs/api.md`, §3.9 (⚠ **шаблонов нет** — текст сочиняет агент под человека, с обращением по имени; одного человека зовём один раз, любой анкетой)
- **Агент инвайтов у соседа** → миграция `RhapsodyAi/migrations/…_wf_dating_invite_write.sql` (⚠ имя уезжает своей переменной `invite_companion_name`: `companion_name` у соседа уже занято дважды)
- **Диалоги по всему сайту** → `.claude/docs/api.md`, §3.8 (⚠ анкета — **фильтр**, а не условие показа; номер анкеты живёт в строке, иначе окно откроется под чужой девушкой)
- **Письмо избранному, который замолчал** → `.claude/docs/api.md`, §3.7.7 (⚠ два предела — **на человека**, а не на сайт: 2 письма в сутки и 4 часа паузы; считается всё ушедшее ему, включая рассылку и ответы. Своего расписания нет — уносит общий круг отправки)
- **Избранные: звёздочка написавшему** → `.claude/docs/api.md`, §3.7.6 (⚠ кнопка на сайте — **переключатель**: жмём только незажжённую звезду, иначе прогон снимет избранное. Работа берётся из входящих писем, выключено по умолчанию)
- **Карточка собеседника** → `.claude/docs/api.md`, §3.7.1 (⚠ заводится каждому адресату письма и кнопкой из ленты; `about` API сайта не отдаёт; переменные адресата не хранятся, а выводятся из карточки)
- **Кому писать первым** → галочка «Приоритет в рассылке» на карточке (`.claude/docs/api.md`, §3.7.1; ⚠ это порядок, а не отбор — неотмеченные остаются)
- **Расписание сменами** → `data/uvicorn/public/js/dating_schedule.js` (⚠ их два: анкеты — `dating_profile.schedule`, рассылки — `dating_site.mailing_schedule`; вид общий, вопросы разные. Идущая смена зелёная, но «действует ли расписание» знает страница, а не модуль)
- **Списки собеседников с сайта** → `.claude/docs/api.md`, §3.3 (⚠ источник — настройка `people_source`: API сайта или сценарий у соседа)
- **Новая настройка панели** → `.claude/docs/api.md`, §6.2 (строка в `setting`, страница «Настройки → Значения»)
- **Показ даты или времени** → `data/uvicorn/public/js/dating_time.js` (⚠ с сервера всё приходит **в UTC**; сдвигает страница по настройке `timezone`)
- **Отказ, который не про анкету** → `src/dating/dating_error.py` (⚠ строка одна на источник; удача её стирает)
- **Свой `httpx.AsyncClient` где-то в коде** → `py_modules/http_/http_pool.py` (⚠ клиент разовый — cookie у каждой анкеты свои, — а транспорт общий: `transport=http_pool_transport()` и **клиента не закрывать**, `aclose()` унёс бы транспорт у всех)
- **Работа с прод-базой или ssh на прод** → `.claude/docs/deploy.md`, §4.5 (⚠ бэкап до записи; защитные правки — отдельным запросом; `--default-character-set=utf8mb4`)
- **Проверка после правок** → `.claude/docs/testing.md`, §1.0 (⚠ сюита разбита на пять групп: `pytest -m chat` — полминуты против трёх минут на всё. Полный прогон — перед выкладкой)
