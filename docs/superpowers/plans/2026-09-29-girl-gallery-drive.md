# Галерея анкеты с Google Диска — план реализации

> **Для агентного исполнителя:** задачи идут по порядку, квадратики `[ ]` отмечают-
> ся по мере дела. Каждая заканчивается прогоном своих тестов и коммитом. Правки
> из одной задачи не переносим в другую: ветка одна, коммиты — по задаче, чтобы
> откат был по задаче же.

**Цель:** третья вкладка в карточке анкеты на «Анкетах» — «Галерея» — фото этой
девушки с Google Диска, ничего не скачивая и не храня у себя.

**Архитектура:** новая наружная дверь `src/drive/drive_api.py` (только Диск:
токен, список папки, байты превью) → механика `src/dating/gallery.py` (как зовётся
папка девушки, что показать, чем ответить) → ручки `src/uvicorn/routers/dating/
gallery.py` (снимок, имя подпапки, прокси картинок, подключение) → вкладка в
карточке «Анкеты». В базе одна колонка: имя подпапки.

**Стек:** FastAPI, Jinja + императивный JS страницы, MySQL (`yoyo`), Redis
(`redis_conn_get`), `httpx` через общий транспорт.

**Спецификация:** `docs/superpowers/specs/2026-09-29-girl-gallery-drive-design.md`
(там решения, цены и открытые вопросы).

## Глобальные ограничения

- **Работаем в worktree `.git_worktree/gallery`, ветка `gallery`** (решение
  человека 2026-09-29). В `master` — ничего, слияние решает человек после выкладки.
- **Живой HTTP наружу нельзя никогда.** У Диска своя заглушка
  `tests/drive_fake.py` на подмене транспорта, как `tests/site_api_fake.py`;
  сторож `py_modules/http_/http_mock.py` стоит на весь прогон и новых побегов
  наружу не простит (`testing.md` §1.2).
- **Секреты не едут наружу.** Refresh-токен и access-токен не попадают ни в URL,
  ни в ответ ручки, ни в журнал: `logging_secret_clean` и никаких заголовков в
  тексте строки журнала. `client_secret` живёт в `.env.local` на сервере, в git —
  только имена переменных в `.env.dist`.
- **Комментарии и docstring по-русски**, и про «почему», а не про «что»
  (`docs-common/code_style.md`). Шапка модуля обязана объяснять, почему этот код
  живёт отдельно — образец `src/dating/site_api.py`.
- **Схема — новый файл в `migrations/`**, применённые не правим; идемпотентность
  через `information_schema` + `PREPARE`, шапка «ЗАЧЕМ / ЧЕМ ОПАСНО / ДО и ПОСЛЕ»
  — образец `migrations/20260929180000_companion_name_parts.sql`
  (`.claude/docs/migration.md`).
- **Тесты не трогают живые анкеты:** своя анкета с доменом `@example.com` и
  удалением в конце (`testing.md` §1.1.1). Сайт для неё — `343` Ladadate из
  снимка соседа (`conftest._STAND_SITES`); выдуманный номер заведение отвергает.
- Прогон: панели должны стоять. Свои группы — `pytest -m core`, `-m profile`,
  `-m page`; полный прогон перед выкладкой.
- ⚠ `.claude/docs-common` — симлинк на общий репозиторий: пишем только в
  `.claude/docs/`.
- ⚠ Статика кэшируется с именем файла; правку CSS/JS видно после
  `Ctrl+Shift+R` (`testing.md` §1.1).

## Задача 0. Креденшалы и способ подключения (делает человек)

Кода в этой задаче нет, и без неё остальные стоят: панель не может попросить у
Google то, чего ей не выдали. Шаги — в Google Cloud Console от имени того
аккаунта, где лежат фото.

- [ ] Проект (или существующий) → **APIs & Services → Enable** → *Google Drive API*.
- [ ] **OAuth consent screen**: External. В *Test users* — адрес того аккаунта,
    чей Диск читаем. Статус остаётся *Testing*; чем это стоит — §3.2 спеки
    (refresh-токен живёт **семь дней**).
- [ ] **Credentials → Create OAuth client ID → Web application**.
    `Authorized redirect URI` — Google сверяет адрес строкой, и регистрация
    предшествует коду: вписать оба, стенд и локальный запуск,
    `https://dating.92.5.17.195.sslip.io/admin/setting` и
    `http://localhost:8021/admin/setting`. Блок задачи 6 покажет ровно эти же
    адреса — разойдутся, и Google ответит `redirect_uri_mismatch`.
    ⚠ Если панель когда-нибудь поедет под `BASE_PATH`, адрес изменится: тогда
    добавляем новый, а не переписываем старый.
- [ ] Мне — `client_id` и `client_secret`. Ложатся в `.env.local` на сервере, в
    git не уходят; в `.env.dist` — только имена.
- [ ] Мне — **ссылка на общую папку** с подпапками девушек (из неё резолвим имена).
- [ ] **Ответ на §10 спеки**, до задачи 4: остаёмся на личном аккаунте с недельным
    переподключением или заводим сервисный (§3.3); как именно названы подпапки —
    по имени девушки, по логину или по её номеру на сайте. Видео показывать
    плиткой — решено 2026-09-29, в плане учтено.

**Проверка:** у двери есть чем дышать (клиент, секрет, папка), и выбор способа
доступа записан в спеке.

```
git commit --allow-empty -m "Галерея анкеты: креденшалы Диска и способ доступа — решение человека"
```

⚠ `client_secret` в переменной окружения, а не в аргументе команды и не в коммите.

## Задача 1. Дверь к Диску

**Файлы:** `src/drive/drive_api.py`, `tests/drive_fake.py`, `tests/test_drive.py`,
`src/dating/request.py`

Три вещи и только три: достать токен, спросить список папки, принести байты
превью. Всё остальное — про анкеты, и живёт в задаче 3.

- [ ] Шапка модуля по образцу `src/dating/site_api.py`: почему отдельная дверь,
    чем она **не** является («это не «дверь наружу вообще»»), где живёт токен.
- [ ] `drive_configured() -> bool` — есть ли клиент с секретом.
- [ ] `drive_token() -> str` — обмен refresh-токена на access в
      `https://oauth2.googleapis.com/token`, снимок в Redis
      (`dating:drive:token`, TTL `expires_in - 120`: запас на обрыв, иначе
      ходим заведомо мёртвым токеном). Секретного в кэше нет: только сам токен и
      срок.
- [ ] `drive_get(path, params) -> dict` — `https://www.googleapis.com/drive/v3` +
    Bearer. `401/403 invalid_grant/token_expired` → **одно** пересвежение и один
    повтор, как в `site_api.py`; второй отказ — наружу словами, а не кодом Google.
- [ ] `drive_children(folder_id) -> list` — `files.list`
    (`q: '<id>' in parents and trashed = false`, `orderBy: 'name natural'`,
    `pageSize: 1000`, `supportsAllDrives`, `includeItemsFromAllDrives`,
    `fields: next_page_token,files(id,name,mimeType,size,createdTime,thumbnailLink,imageMediaMetadata,videoMediaMetadata)`),
    обход `pageToken` с потолком страниц.
    ⚠ Кавычки в `q` — только через подстановку `folder_id`, а `folder_id` приходит
    из ответа Диска, а не с клавиатуры; имена папок в `q` не подставляем вовсе
    (см. задачу 3, там поиск по имени идёт по снятому списку).
- [ ] `drive_bytes(url) -> (bytes, content_type)` — GET чужого адреса **с Bearer**
    (приватное превью иначе не отдаётся) и без перенаправления на аутентификацию:
    `302` на `accounts.google.com` — отказ «доступа нет», а не байты страницы входа.
- [ ] Отказ — своим классом `DriveError` со словами для человека
      («Диск не подключён», «папки нет», «Диск молчит», «доступа нет»).
      HTTP-кодов она не знает: решает ручка.
- [ ] Журнал: `REQUEST_DRIVE = 'drive'` и строка `'диск'` в `REQUEST_DOORS`
      (`src/dating/request.py` — страница берёт названия отсюда, своей копии у
      вкладки быть не должно); путь — без токена, тел нет.
- [ ] Транспорт общий: `httpx.AsyncClient(transport=http_pool_transport())`,
    клиента **не закрывать**.
- [ ] `tests/drive_fake.py` — подмена транспорта: словарь ответов, счётчик
    обращений, режимы `401` однократно, пустая папка, две страницы, `404`, обрыв.
    Выключатель журнала — как у `site_api_fake.py` (`request_off`).

**Проверка:** `pytest tests/test_drive.py -q -m core` — токен из кэша вторым
вызовом не спрашивается; после `401` ровно один повтор и не больше; две страницы
склеиваются в один список; отказ называется словом; в тексте отказа нет ни токена,
ни `client_secret`.

```
git commit -am "Галерея анкеты: дверь к Google Диску — один токен, список папки, превью"
```

## Задача 3. Механика галереи

**Файлы:** `src/dating/gallery.py`, `tests/test_gallery.py`

- [ ] `gallery_folder_name(profile) -> str` — вписанное имя; пусто → логин
      анкеты; и то и то не найдено → её номер на сайте. Порядок фиксирован и
      написан на вкладке, чтобы человек не угадывал.
- [ ] `gallery_view(profile_id, refresh=False) -> dict` —
      `{files: [{id, kind: 'image' | 'video', name, thumb, view_url, width,
      height, seconds}], folder, folder_found, other_count, why, taken_at}`.
      В плитку идут `image/*` и `video/*`; прочее — `other_count`. `view_url`
      собирает **сервер** (`https://drive.google.com/file/d/<id>/view`), чтобы
      страница не строила адреса Google сама и не разошлась с нами.
- [ ] Снимок в Redis `dating:gallery:{profile_id}` на 15 минут; повторный запрос
      в срок **не ходит на Диск вовсе** — это и есть ответ на «у нас нет много
      памяти» и на квоты Google.
- [ ] ⚠ **Отказ не стирает прежний снимок.** Диск молчит — отдаём последний
      снимок с `taken_at` и словами «Диск молчит»; пустая плитка без причины
      читается как «у девушки нет фото», и человек пойдёт заводить папку заново.
- [ ] ⚠ **Отказ про протухший токен отличается от «папки нет»** — и то и другое
      летит в `error_write(source='drive', …)` (`src/dating/error.py`), удача
      стирает строку.
- [ ] Отказ «папки нет» дополняется первыми именами из общей папки: человек
      обязан увидеть, как их называют на самом деле.
- [ ] Порядок — `name natural`, как просил `orderBy`: сетка не должна прыгать
      между обновлениями.

**Проверка:** `pytest tests/test_gallery.py -q -m core` — два вызова подряд это
один поход на заглушку; после обрыва отдаётся прежний снимок с пометкой; в
`files` попадают фото и видео, документ — только `other_count`; у каждой фразы
отказа она одна и та же в модуле и в тесте.

```
git commit -am "Галерея анкеты: снимок папки девушки, отказ словами и прежний снимок"
```

## Задача 4. Ручки вкладки

**Файлы:** `src/uvicorn/routers/dating/gallery.py`, `tests/test_gallery_http.py`,
`main_uvicorn.py`

- [ ] `router = APIRouter(prefix='/api/dating/gallery', tags=['dating'])`,
      `include_in_schema=False` — по укладу раздела.
- [ ] `GET /{profile_id}` — снимок (все вошедшие). ⚠ Анкеты нет → `404`, а не
      пустая галерея: «нет анкеты» и «нет фото» — разные вещи.
- [ ] `PUT /{profile_id}/folder` — имя подпапки (все вошедшие). Пустое значение
      **стирает** колонку — «не знаю», и дальше работает резервный порядок.
      ⚠ Имя не чистим и не переиначиваем: как вписали, так и ищем.
- [ ] `GET /{profile_id}/img/{file_id}?w=400|1600` — прокси превью: байты с
      Bearer, `Cache-Control: private, max-age=3600`, тип из ответа Диска.
      Превью видео — тот же `thumbnailLink` (первый кадр), дорога одна.
      ⚠ Токен не в URL и наружу не едет; `w` берём из замкнутого набора,
      произвольный размер — `422` (просьба «самого низкого качества» живёт
      здесь, а не в догадках страницы).
      ⚠ `file_id` проверяется принадлежностью этой анкете (снимок задачи 3):
      иначе одна анкета отдавала бы чужие фото по чужому номеру.
      ⚠ **Самих видео мы не отдаём никогда** — только превью; полный кадр у
      видео спрашивается ссылкой Диска в новой вкладке (§4 спеки).
- [ ] Админские: `GET /status` (клиент есть, токен есть, когда подключали,
      последняя неудача; **значений секретов наружу нет**), `POST /connect/start`
      (отдаёт ссылку согласия с `state` в Redis на 10 минут и показывает, какой
      `redirect_uri` зарегистрировать), `POST /connect` (меняет `code` на
      refresh-токен и пишет `setting_set(..., dynamic=1)` — пометка прячет строку
      из списка настроек §6.2), `POST /disconnect`, `PUT /root` (общая папка).
      ⚠ `state` сверяется: без него чужой `code` стал бы подключением чужого
      Диска к нашей панели.
- [ ] Регистрация в `main_uvicorn.py` — импорт рядом с остальными ручками
      анкет и `include_router`.

**Проверка:** `pytest tests/test_gallery_http.py -q -m "core or profile"` —
роль `dating` на `/status`, `/connect`, `/root` получает `403`; снимок чужой
анкеты и прокси чужого файла — отказ; в теле `/status` нет ни токена, ни
подстроки секрета; `PUT folder` round-trip на своей анкете; в ответе нет сырых
значений `client_secret`.

## Задача 5. Вкладка «Галерея» в карточке «Анкет»

**Файлы:** `data/uvicorn/template/admin/dating/index.html`,

- [ ] ⚠ **Гонка запросов — как в `profileLoad`:** `requestId` сверяется до

- [ ] Поле «Папка с фото» + «Сохранить» + «Обновить». Подсказкой рядом — резервный

- [ ] Плитки `w=400` — фото и видео рядом. Щелчок по фото — кадр `w=1600` поверх

      ⚠ Просмотрщик Диска смотрит на сессию Google в браузере, а не на наш токен:
      у того, кто не сидит под тем аккаунтом, откроется «запросить доступ». Это
      известное ограничение v1, и оно касается только видео.

## Что остаётся за планом

- **Видео потоком.** Плитка видео — превью, полный кадр отдаёт просмотрщик Диска
  и требует сессию Google в браузере. Свою отдачу с `Range` не заводим: это
  десятки мегабайт через панель, а человек просил ничего не качать.
- **Отправка фото в чат.** Решение человека — не хранить байты, значит «отправить
  диск-фото» требует либо временного скачивания в память, либо отдачи ссылки на
  наш прокси наружу. Оба — отдельный разговор, и к нему стоит вернуться, только
  когда вкладкой пользуются.
- **Медиа-пул персон** (`docs/superpowers/specs/2026-09-14-media-pipeline-diana-design.md`)
  — другая задумка, кода нет; галерея её не трогает.
- **Сервисный аккаунт** вместо личного (§3.3) — если недельное переподключение
  станет обузой: способ добычи токена в `drive_api.py` и настройка, всё остальное
  целиком.
