# Две галочки в блоке «Настройки анкеты»

**Дата:** 2026-09-05
**Страница:** `/admin/dating`, правая колонка, блок «Настройки анкеты»

## Задача

В блоке «Настройки анкеты» сейчас один выключатель — «Анкета включена». Добавить
рядом два: **«Чат автоответ»** и **«Письма рассылка»**.

## Что это за галочки

**«Чат автоответ» — существующий флаг `dating_profile.auto_answer`.** Тот же, что
галочка «ai-ответ» на «Профилях» (`dating_profile.html:914`) и в окне переписки
(`dating_profile.html:1905`). Круг воркера его читает (`dating_auto.py:62`), ручка
`PUT /api/dating/profile/{id}/auto` его правит, карточка анкеты его уже отдаёт
(`dating_profile_view.py:287`) — но блок «Настройки анкеты» его не рисует. Работа
здесь только на странице: ни колонки, ни ручки заводить не надо.

**«Письма рассылка» — новый флаг, задел.** Механики рассылки в проекте нет: на
«Профилях» есть вкладка с таким именем (`dating_profile.html:643`), но её тело —
заглушка. Галочка заводит колонку и ручку, чтобы решение человека где-то хранилось;
исполнителя напишет отдельная задача.

⚠ **Три флага, и они про разное.** `enabled` — «ведём ли анкету вовсе»,
`auto_answer` — «отвечает ли за неё агент в чате», `mailing_on` — «шлём ли от неё
рассылку писем». Свести их значило бы отнять законные состояния: анкету ведут
руками (включена, автоответ снят), и анкета отвечает в чате, но не рассылает.

## Схема

Новая миграция `migrations/20260905120000_dating_profile_mailing.sql` по образцу
`20260903110000_dating_profile_schedule_on.sql`: идемпотентное добавление колонки,
замеры «ДО» и «ПОСЛЕ».

```sql
ALTER TABLE `dating_profile`
    ADD COLUMN `mailing_on` TINYINT(1) NOT NULL DEFAULT 0
        COMMENT 'Рассылка писем: флаг задела, исполнителя пока нет'
        AFTER `auto_answer_only`
```

⚠ **Умолчание `0`, в отличие от `auto_answer` (там `1`).** Показать включённой
галочку у функции, которой нет, значит соврать: человек решит, что рассылка идёт.

**Индекса нет.** Отбирать по колонке некому — круга рассылки не существует. Индекс,
который никто не читает, платится на каждой записи. Заведёт его та задача, которая
напишет круг, — как `idx_dating_profile_sched` завела задача расписания.

`auto_answer` не трогается вовсе.

## Ручка

Новая: `PUT /api/dating/profile/{id}/mailing`, в
`src/uvicorn/routers/dating/dating_profile_action.py`, рядом с `/schedule-on` и
`/enabled`, по их форме.

```python
class DatingProfileMailing(BaseModel):
    """Рассылка писем: флаг задела, исполнителя пока нет."""

    mailing_on: bool = Field(..., description='Слать ли рассылку писем')
```

Тело: `dating_profile_row(profile_id)` (404, если анкеты нет) → `UPDATE` → `commit`
→ `dating_log_write(profile_id, 'info', 'Рассылка писем включена|выключена')` →
ответ `{'result': {'mailing_on': ...}}`.

**Побочных действий нет**, и докстрока говорит это прямо: исполнителя пока нет,
флаг только запоминает решение. Без такой строки через месяц это читается как
забытый баг — «поставил, а ничего не происходит».

**«Чат автоответ» ходит в существующую `PUT /api/dating/profile/{id}/auto`.**
Ручка не меняется.

⚠ **У `/auto` есть побочное действие:** включение сразу разбирает накопившееся и
может отправить ответы, не дожидаясь круга воркера
(`dating_profile_action.py:397-405`). На «Профилях» так уже работает, и галочка в
«Настройках анкеты» будет вести себя так же — одна ручка, одно поведение везде. Из
подписи это не очевидно, поэтому сказано в пояснении под галочкой.

**Отдача на страницу.** В `dating_profile_view_card` (`dating_profile_view.py`),
там же, где `enabled` и `auto_answer`, добавляется
`'mailing_on': bool(profile.get('mailing_on'))`.

В список анкет (`dating_profile.py:126`) флаг **не** добавляется: блок читает
карточку, а списку он сейчас не нужен. В `uvicorn_validation.py` — тоже нет:
`schedule_on` там отсутствует по той же причине, род ошибки у булева один.

## Страница

`data/uvicorn/template/admin/dating.html`, функции `settingsBlock` и `settingsBind`.

### Раскладка

```
НАСТРОЙКИ АНКЕТЫ
  ☑ Анкета включена       ← как сейчас
  ☑ Чат автоответ         ← новое
  ☐ Письма рассылка       ← новое
  ── Пароль ──
  ── Расписание ──
  ── Удалить анкету ──
```

Три галочки идут подряд, до блока пароля: все три про одно — как эту анкету ведут.

### Сборка строки

Три почти одинаковых куска разметки собираются одной функцией
`setRow(id, on, title, note, dim)`: три копии разошлись бы в мелочах (класс `off`,
отступы), а мелочи в этом блоке и есть смысл.

`dim` — вешать ли класс `off` на снятую галочку, то есть приглушать ли строку. У
первых двух `true`, у рассылки `false` (почему — ниже).

### Приглушение — разное у разных строк

`.prof-set-row.off` красит подпись жёлтым: «выключено видно, не читая подписи».

- **«Анкета включена»** — приглушается, как сейчас.
- **«Чат автоответ»** — приглушается: состояние редкое и значимое.
- **«Письма рассылка»** — **не** приглушается. Умолчание `0`, то есть жёлтая строка
  загорелась бы у всех анкет сразу и навсегда. Жёлтый везде — жёлтый нигде.

### Пояснения под подписями

В стиле блока — их читают один раз и запоминают:

- **Чат автоответ:** «Отвечает агент, а не человек. Включение сразу разбирает
  накопившееся — ответы могут уйти прямо сейчас.»
- **Письма рассылка:** «Рассылка ещё не работает: галочка только запоминает
  решение.»

Отдельной пометки «не действует у выключенной анкеты» нет: пояснение под самим
выключателем двумя строками выше уже говорит «выключенную анкету воркер не ведёт:
не отвечает и ничего не отправляет».

### Обработчики

По образцу `enabledBox`. Каждый **запирает свою галочку на время запроса**: круг
перерисовки идёт каждые 15 секунд, и второе нажатие уехало бы раньше, чем вернулся
ответ на первое, — состояние в базе разошлось бы с галочкой. При отказе галочка
возвращается в прежнее положение, причина — в `say(..., true)`.

- **`autoBox`** → `PUT /auto` с `{auto_answer}`. Ответ несёт `answered` — словарь
  разбора (`asked`, `sent`, `silent`, `offline`, `errors`) либо **пустой** `{}`,
  если агента у анкеты нет. Отсюда чтение через умолчание:
  `const sent = (answered && answered.sent) || 0`. Сколько ушло — говорится словами
  («автоответ включён, отправлено N»), раз ответы могли уйти прямо сейчас. Если
  `sent` не ноль, зовётся `profileLoad()`: собеседницы в карточке изменились.
  `profilesLoad()` не зовётся — список слева про автоответ ничего не рисует
  (`dating.html:560` рисует только значок выключенной).
- **`mailingBox`** → `PUT /mailing` с `{mailing_on}`. Перезагружать нечего, только
  `say()`.

## Тесты

Новый файл `tests/test_profile_mailing.py` по образцу `TestEnabledEndpoint` из
`test_profile_enabled.py`: одноразовая анкета в живой базе, ручки зовутся в
процессе, а не по HTTP (заведение сверяет сайт у соседа — по HTTP это дало бы два
запроса к RhapsodyAi на каждую тестовую учётку, то есть сюиту, падающую от его
перезапуска).

| Тест | Что стережёт |
|------|--------------|
| `test_new_profile_has_mailing_off` | Умолчание `0`. ⚠ Не как у `enabled`: там «ведём», здесь «не рассылаем», и разница намеренная |
| `test_toggle_is_stored` | Щёлкнули туда-обратно — читается из базы |
| `test_mailing_is_independent` | Рассылка не задевает `enabled` и `auto_answer`, и наоборот: состояние «ведём руками, рассылка стоит» достижимо |
| `test_mailing_reaches_the_card` | Флаг доезжает до `dating_profile_view_card` — иначе после перезагрузки страницы галочка соврала бы |
| `test_page_carries_the_boxes` | `/admin/dating` под `auth_client` отдаёт разметку с `id="autoBox"` и `id="mailingBox"`: блок собирается скриптом, но скрипт лежит в шаблоне. Сторожит от того, что галочки молча выпадут при следующей правке |
| `test_unknown_profile_is_404` | Правка несуществующей анкеты — ошибка вызывающего, и знать о ней он должен |
| `test_closed_without_login` | По HTTP под `client` (без входа): 401 |

Теста «воркер флаг не читает» нет: проверять отсутствие поведения, которого не
существует, нечем — такой тест сторожил бы пустоту.

## Что в эту задачу не входит

- **Сама рассылка писем** — круг воркера, кому пишем, чем отправляем (API сайта или
  сценарий у соседа), как часто. Отдельная задача.
- **Перестройка вкладок «Профилей»** — вкладки поднимаются над колонками, у каждой
  свой список профилей. Следующая задача после этой.
