# Медиа-конвейер анкет: пачка фото персоны «diana»

**Дата:** 2026-09-14
**Где живёт:** `data/girls/diana/` (пул медиа), генерация — ферма gx10-2 (`192.168.1.2`)

## Задача
Проверь деплой. 
Профилям нужны фото и видео для отправки собеседникам в чате, и они должны быть
постоянно. Первая пачка — **50 кадров персоны diana** (брюнетка ~28, Киев): 40 SFW
в анкету + 10 умеренно-интимных в чат. Пачка ложится в `data/girls/diana/` —
коллекция персоны: имя папки = имя персоны, файлы с именами-hex, EXIF/GPS срезаны.

## Путь (почему так)

Лицо и фигура персоны — **синтетические**: reverse-image search по чужим анкетам
не бьёт, авторских прав нет, геолокация чужого города не уезжает вместе с фото.
Instagram/TikTok-кадры — только как референсы сцен и поз. Интимные кадры — та же
персона и та же сцена в промпте: лицо и фигура совпадают по построению, никакого
face-swap. Правила LadaDate: в анкете лицо открыто, эротика запрещена — значит
анкета только SFW, интимные кадры живут в пуле с флагом `nsfw` и уходят в приватный чат.

## Ферма gx10-2 (что есть, что настраивать)

Машина `gx10-de02` (Ascent GX10, GB10, 121 ГБ unified-памяти, ~92 ГБ свободно),
`192.168.1.2`, SSH-хост `gx10-2`. ComfyUI — контейнер `comfyui-gb10`
(compose `~/comfyui-gb10`, вход `--listen 0.0.0.0 --port 8188`). ⚠ Запущенный
контейнер стартован из старого compose **без проброса порта** — с сети ComfyUI
не виден; `8189` — это чужая служба `reels_tts`, её не трогать. Настройка:
пересоздать контейнер из текущего compose (там `8188:8188`).

Модели на ферме: `flux1-dev-fp8` (фото), `pulid_flux_v0.9.0` (консистентность
лица без обучения), `clip_vision_h`, `t5xxl_fp8`, `Wan2_2-TI2V-5B` + umt5 (видео —
фаза 2), каталог `loras/` пуст. Трейсера LoRA нет — для первой пачки он и не нужен.
QA-эмбединги: каталог `models/insightface` пуст — доустанавливается на ферме.

## Пул медиа и имена файлов

`data/girls/<имя-персоны>/` — файлы `<32hex>.jpg` (как сайт ключует анкетные фото
по hex-имени, см. `.claude/docs/dating.md` про `photo`), EXIF/GPS режутся при
склейке (`exiftool -all=`). Рядом `manifest.json` — по файлу строка: сцена, теги
`nsfw`/`face_on`, статус. Колонки БД, статус `new → queued → sent` и отправка в чат
(`dating_media_send`) — **фаза 2, вне объёма этой спеки**; здесь только файлы и манифест.

## Состав пачки (50 кадров)

**40 SFW (в анкету):** 8 портретов (оконный свет, mirror-selfie, с улыбкой/серьёзная) ·
6 full-body (улица, парк, море) · 6 быта (кухня, кавоварня, цветы) · 5 хобби (йога,
холст, книга, кот) · 5 город (Крещатик, София, Лвов, Одеса) · 4 праздничного (ялинка,
вечернее платье, ресторан) · 3 спорта · 3 разговорника (вареники, листівка, букет).

**10 интимных (в чат):** шовконове пеньюар ×3 · кружевное бельё ×2 · утренний свет
из-за силуэта ×2 · море с силуэта без головы ×1 · ванна с пеной по ключицы ×2.
Уровень — topless/бельё, без explicit.

## Процесс пилота

1. **Якорное лицо:** Flux + PuLID-лист лица (анфас/ракурсы/улыбка) → человек
   подтверждает лицо одним просмотром сетки.
2. **Эмбеддинг якоря:** insightface (buffalo_l) на ферме, косинус как метрика QA.
3. **Батч:** workflow Flux+PuLID, сцена = промпт-блок из таблицы составов, кадры
   идут в `data/girls/diana/` с hex-именами и без EXIF.
4. **QA:** косинус эмбединга кадра против якоря ниже порога — брак, переработка
   один раз, порог подбирается на пилоте эмпирически (старт 0.5).

## Инструменты (общий слой)

По `py_modules/docs/tool_rules.md` §1 всё универсальное живёт в `py_modules`,
проект носит только данные (workflow, сцены, якорь, манифест) и указатель submodule:

| Что | Модуль |
|---|---|
| батч персоны через ComfyUI API (workflow+сцены → кадры, EXIF, hex-имена, манифест) | новый `comfy_/comfy_gen.py` |
| косинус «то же лицо» (buffalo_l) | новый `ai/ai_face.py` |
| сетки кадров, правки заплатками, тон пачки | существующие `image_/` (`image_fix`, `image_match`), ffmpeg |
| видео (фаза 2) | те же workflow-батчи + `image_frames` для кадров/полотен |

## Отказы и проверки

Ферма не отвечает / генерация упала — пилот останавливается с внятным текстом
(в фазе 2 это станет строкой `dating_error`). Проверка каждого шага пилота —
команда с выводом (curl, сетка кадров), факт фиксируется в манифесте.
