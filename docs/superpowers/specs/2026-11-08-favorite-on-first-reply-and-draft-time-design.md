# Звезда ответившему у сайта без API и время черновика в разговоре

08.11.2026

Две правки, связанные одним случаем с прода: Marina → Lance на Step2Love. Он
ответил на приглашение, чат закрылся раньше, чем ответ был готов, — и в окне
разговора не видно ни того, когда ответ написан, ни того, что человек, однажды
ответивший, так и не попал девушке в избранные.

## 1. Круг избранных берёт сайт с ручкой, а не только сайт с API

### Как сейчас

Занятие «ответил — в избранные» уже описано кругом `favorite_round.py`, и
триггер у него тот самый, который нужен: `_senders` берёт работу из `mail_in`
**и** из входящих `message`. У Step2Love входящая реплика приезжает импортом
панели именно в `message`, то есть работа у круга есть.

Обе двери к сайту тоже уже разведены по драйверу:

| Что | Дверь | Step2Love |
|-----|-------|-----------|
| список избранных | `favorite_uids` → `_handle_uids` | кадр авторизации сокета, `favoriteList` |
| нажать звезду | `favorite_add` → `_by_handle` | `POST /ajax.php?com=ajax` |

Не работает ровно одно место — `favorite_round._work`:

```python
base = str(await _setting(site_id, 'api_base')).strip()
if not base:
    return None
```

Сайт без `api_base` уходит ни с чем. У Step2Love API нет и не будет, поэтому
занятие для него не работает вовсе — при полностью готовых обеих дверях.

### Что делаем

Условие прохода становится «есть `api_base` **или** у сайта есть своя ручка»:

```python
base = str(await _setting(site_id, 'api_base')).strip()
if not base and not await _by_handle(site_id):
    return None
```

`_by_handle(site_id)` спрашивает драйвер: `site_registry_favorite(await
site_presence(site_id)).by_handle()`. Ответ **не** кешируется: настройка сайта
и так читается через `site_setting`, и второй слой памяти разошёлся бы с ней.

`base` и `password` у такого сайта остаются пустыми строками и никем не
читаются: `favorite_uids` и `favorite_add` уходят в драйвер раньше, чем
смотрят на них.

Пауза между звёздочками (`FAVORITE_PAUSE_SEC`) и потолок за заход
(`favorite_batch`) остаются общими на обе дороги. У ручки они почти ничего не
стоят, но развилка «у ручки потолка нет» завела бы второе правило там, где
сегодня одно.

⚠ Шапку `favorite_round.py` правим вместе с кодом: раздел «Без API сайта круг
не работает — и это не ограничение, а следствие» перестаёт быть правдой. Довод
там записан убедительно («письма приходят той же ручкой»), и оставленный
нетронутым он вернёт правку назад при первом чтении. Новый текст называет
различие: список и звезда спрашиваются **у драйвера**, а дорога, которой
приходит ответ, у сайта без API своя — импорт панели.

### Чем сторожим

Два теста рядом с существующими в сюите избранных:

1. сайт с ручкой и **без** `api_base` — круг его берёт, звезда нажата
   (драйвер подменён);
2. сайт без `api_base` и без ручки — круг уходит, на сайт не ходит вовсе.

### Настройка прода

У Step2Love (`999345`) ключа `favorite_on` нет вовсе, то есть занятие выключено
и после выкладки кода ничего не изменится. Ставится после выкладки запросом к
базе прода с бэкапом до записи: `favorite_on = 1`, `favorite_every` — как у
Ladadate (300 с).

## 2. Время черновика видно в окне разговора

### Как сейчас

`chat_reply_pending` отдаёт `created_at` черновика, а роутер
(`profile_view.profile_view_messages`) его **выбрасывает**: строка уходит на
страницу с `created_at: None`. Это решение, и оно верное — с временем карточка
встала бы между репликами и читалась бы как отправленная.

Цена решения видна на случае Lance: его реплика в 18:47, карточка «ответ в
пуле» без времени, и вопрос «за сколько мы готовили ответ» с экрана не
отвечается никак. А ответ на него тут главный: чат закрылся за эти секунды.

### Что делаем

Роутер кладёт время черновика **отдельным полем** `made_at`; `created_at`
остаётся `None`, порядок и место карточки не меняются.

Страница у карточки с `pending` пишет рядом с меткой «ответ в пуле»:

```
ответ в пуле · написан 18:47, через 40 с
```

— где «через 40 с» это промежуток между его последней входящей репликой и
`made_at`. Считает страница: оба времени уже лежат в том же списке, сервер
второй раз о них не спрашивают.

⚠ Слово «написан», а не голая метка времени: у соседних реплик метка значит
«сказано», и одинаковый вид у сказанного и ненаписанного — ровно та беда, от
которой `created_at` здесь и обнулён.

Промежуток показывается только когда входящая реплика в списке есть. Нет её
(черновик к реплике, уехавшей за край страницы) — остаётся «написан 18:47».

### Чем сторожим

Тест ручки: у строки черновика `created_at is None` **и** `made_at` равен
времени строки `chat_reply`. Первая половина не украшение — она и есть то
решение, которое легко отменить, перепутав поля.
