# Записанные кадры чата

Здесь лежат кадры вебсокета в том виде, в каком они приходят по проводу — **строками**,
а не разобранными объектами. Строкой потому, что разборщик получает именно строку:
кадр с невалидным JSON внутри или JSON-массив вместо объекта — это тоже случаи, и
храня их объектами, мы бы их потеряли.

По файлу на сайт: `<сайт>_chat.json`. Ключ — имя случая, значение — сырой кадр.

## Зачем они

Протокол чата зашит в `dating_chat.py` и `dating_send.py` константами под
Goldenbride. Правильность разбора сейчас доказывается только живым сайтом: имена
методов, вложенный JSON в поле `message`, формат идентификатора и порядок кадров
подтверждения проверить иначе нечем.

Эти файлы — фиксация **текущего** поведения перед выносом протокола в драйверы
сайтов. Тесты, которые их читают (`test_chat_frames.py`, `test_send_frames.py`),
написаны до переноса кода намеренно: они и есть доказательство, что перенос
ничего не изменил.

## Откуда взяты значения

Из кода и `.claude/docs/dating.md`, где форма кадров описана по разбору живого
обмена. Каждый случай — та мелочь, на которой система уже спотыкалась, и почти у
каждого в комментарии теста написано, чем именно она обошлась:

| Случай | Чем обошёлся |
|--------|--------------|
| `incoming_echo` | своё же сообщение показывалось человеку как новое |
| `incoming_from_man` | отсев по `isMan` глушил ровно те сообщения, ради которых всё затевалось |
| `pending_empty` | пустой `content` в запросе истории → сервер отвечает «ничего нет», и всё пропущенное терялось |
| `ack_echo_client` | эхо принимали за доставку; сообщения не доходили ни до кого |
| `refuse_words` | отказ сайта выглядел как наш сбой |
| `offline_user` | «собеседник не в чате» выглядело как «не подтвердил приём» |

**Значения не выдуманы наугад, но и не сняты с живого сайта.** Это восстановленная
форма: настоящих кадров в базе не осталось (там лежит уже разобранное), а живой
сайт для снятия требует рабочей учётки. Если однажды кадры снимут с провода —
заменить содержимое файлов можно, не трогая тесты: их задача проверять разбор, а
не конкретные номера.

Номера собеседников и тексты безличны намеренно: файлы лежат в репозитории.

## Страница анкеты в админ-панели

`ladadate_lady_edit.html` — форма со страницы `/partner/agency/userprofile/edit/{ID}`,
снятая с живой панели 12.10.2026 читающим GET по удерживаемой сессии. В отличие от
кадров чата выше, это **не восстановленная форма, а настоящая**: разметка, имена
полей и классы приехали с сайта как есть.

Имена здесь и есть главное: разбор идёт **по ним**, а не по подписям («HEIGHT»
нарисована рядом и станет другой при первом переводе интерфейса, а `name="HeightId"`
переживёт перевёрстку). Списки `option` укорочены до трёх с сохранением выбранного —
в живой странице их 236 у одной только страны.

⚠ Сущности здесь не случайны: `5&#39;8&quot; - 172 cm` — то, как панель пишет рост,
и разбор обязан их разворачивать (`convert_charrefs=True`).

⚠ Значения обезличены по правилу этой папки: номер, имя, город и три текстовых
блока заменены. Разметку и имена полей менять нельзя — в них весь смысл образца.
